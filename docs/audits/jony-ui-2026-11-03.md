# Audit UI à zéro et refonte guidée — 2026-11-03

État : audit fait sur le code, sans exécuter l'app. Les points qui demandent l'app lancée (VoiceOver réel, Échap
dans les sheets, rendu Liquid Glass) sont marqués **à vérifier**.

Ce qui n'a pas pu être fait :
- App non lancée : aucune capture, aucun test VoiceOver. Pour le faire : `make run` sur un Mac avec `.wine-runtime/`.
- Décision AuDHD absente de `CLAUDE.md` : pas de section AuDHD dans ce rapport. Question à poser à l'utilisateur :
  « Appliquer le guide AuDHD aux interfaces de ce projet ? ». Réponse à écrire dans `CLAUDE.md`, section `## Interface AuDHD`.
- Passe `impeccable` non lancée : il n'y a pas de rendu à juger. Elle est prévue sur le canvas (lot 6).

Légende : **P0** bloque un parcours ou casse l'accessibilité. **P1** casse une règle HIG visible.
**P2** cohérence ou finition. Règles citées par leur id dans le vault HIG (capture 2026-09-15).

### 1.7 Transverses

**Localisation (P0 pour `fr`).** `fr` est déclaré dans `knownRegions` (`WoWSilicon.xcodeproj/project.pbxproj:193-197`),
mais le dépôt n'a **aucun** `.xcstrings` ni `.strings`. Obstacles à lever avant de traduire :
- pluriels construits à la main : `MainDashboardView.swift:211`, `:438` ;
- chaînes d'état venues des ViewModels et affichées par `Text(variable)`, qui ne passent pas par le catalogue :
  `MainDashboardView.swift:658`, `PatchingStatusChecker.swift:16-48`, `MainDashboardViewModel.swift:1815` ;
- libellés construits avec deux-points et largeurs fixes (`MainDashboardView.swift:46-49`, `:560`) : ils cassent dès que le français est plus long ;
- « World **Of** Warcraft » : `MainDashboardViewModel.swift:1493`, `:1516`, `:1518`. Le nom correct est « World of Warcraft ».

**Clavier (P1).** Pas de raccourci pour Play, ni pour Options (⌘,), ni pour un nouveau profil (⌘N). Le sélecteur de profil n'est pas navigable aux flèches. `accessibility-018`, `the-menu-bar-010`.

**Clair / sombre (P2).** Le fond doré et le dégradé du bouton sont identiques dans les deux modes (`DashboardBackgroundView.swift:7`). Le filet blanc du logo (`MainDashboardView.swift:540`) ressort fort en sombre. `dark-mode-002`, `dark-mode-005`.

**Taille du texte (P2).** macOS n'a pas Dynamic Type. Les tailles fixes `.system(size:)` (`MainDashboardView.swift:380`, `:672`, `:690`, `:705`, `:830`, `:879`, `:884`) ne suivent pas le réglage de taille de texte de la barre latérale ni les styles du système. `typography`, `accessibility-001`.

## 5. Refonte guidée par l'audit

### 5.1 Architecture d'écrans cible

```
Fenêtre principale (redimensionnable, min 760 × 520, défaut 960 × 620)
├─ Barre latérale : profils
│   ├─ World of Warcraft · 32 bits   (1.12 · 2.4 · 3.3)
│   ├─ World of Warcraft · 64 bits   (8.3)
│   └─ Autres jeux D3D9
│   menu contextuel : Renommer · Afficher dans le Finder · Supprimer (annulable ⌘Z)
├─ Barre d'outils : [Aperçu | Addons | Mods | Realmlist | Profil]  ·  Nouveau profil (+)  ·  état Wine
└─ Détail
    ├─ En-tête : nom du profil · « WoW 8.3.7 · 64 bits » · bouton Lancer (états)
    ├─ Aperçu : section « Prêt à lancer » (lignes d'état symbole + texte + 1 action)
    ├─ Addons / Mods / Realmlist : vues pleines (Table, ContentUnavailableView, glisser-déposer)
    └─ Profil : réglages par profil (graphismes, audio, x87, lanceur tiers, variables d'environnement)

Réglages (⌘,)  — fenêtre Settings, une barre d'outils à onglets
├─ Général : mises à jour, statistiques anonymes
├─ Wine : bouteille (chemin, migration), Retina, Option → Alt, winecfg, terminal Wine
├─ Dépendances : Rosetta, VC++ (x86 et x64), Wine Mono, Git
└─ Dépannage : diagnostics d'accès, journal, actions destructives (confirmées)

Premier lancement : une seule sheet d'accueil (migration, bouteille, statistiques, Rosetta), à la place de 4 alertes.
```

Onglets non pertinents (Mods et Realmlist pour BfA) : grisés dans le sélecteur, avec une info-bulle
(« Le client 8.3.7 n'utilise pas realmlist.wtf »). On ne les masque pas, pour que la barre d'outils garde
la même forme d'un profil à l'autre (correctif de O4).

### 5.3 Parcours BfA cible

1. ⌘N ou « + » : la sheet demande d'abord **l'exécutable** (bouton ou glisser-déposer d'un `.exe`).
2. L'app lit l'architecture PE et **présélectionne** le modèle (x86-64 → « World of Warcraft 8.3.7 · 64 bits »).
   Le choix reste modifiable ; une incohérence s'affiche en ligne dans la sheet, avant la création, et non plus dans une alerte après coup.
3. Le nom est prérempli avec le nom du dossier.
4. « Créer » : le profil s'ouvre sur l'Aperçu, déjà prêt si rien ne manque.
5. ⌘↩ lance ; l'en-tête montre l'état de lancement.

## 6. Décisions #34, #36, #37, #38

### #34 — Relever la cible minimale à macOS 26 ?

**Recommandation : non. On garde macOS 14 en déploiement et on compile avec le SDK macOS 26.**
- La doctrine de `docs/design.md` réserve le verre au chrome système (`materials-001`, `materials-002`). Une barre
  d'outils, une barre latérale et une scène `Settings` compilées avec le SDK 26 prennent Liquid Glass d'elles-mêmes sur
  macOS 26, et gardent les matériaux classiques sur 14 et 15. Le design ne demande aucun `.glassEffect` : il n'y a
  donc rien à replier.
- Tous les composants cibles existent en macOS 14 : `NavigationSplitView`, `Settings`, `ContentUnavailableView`, `Table`, `LabeledContent`.
- Le seul usage qui exige macOS 26 côté produit (le pilote KosmicKrisp) est déjà géré à l'exécution (`GraphicsSectionView.swift:97-99`, `:121-128`). BfA x64 tourne sur MoltenVK.
- Relever la cible couperait les mises à jour Sparkle des utilisateurs en 14 et 15, sans gain visible pour eux.
- À réévaluer avec les statistiques anonymes (champ « version de macOS », déjà collecté) quand la part de 14-15 sera faible.

Alternatives écartées : macOS 26 seul — perd des utilisateurs pour un gain que le design n'utilise pas. macOS 15 —
ne gagne que `MeshGradient`, que la refonte supprime.

### #36 — Signature visuelle faible

**Recommandation : garder la sobriété et concentrer la signature sur trois points seulement : l'icône, le bouton Lancer en laiton avec ses états animés, et les glyphes de profil.**
- La plainte « interchangeable » vient d'un écran de maquette sans contenu. Dans l'app, ce qui distingue, ce sont les
  profils (1.12, 3.3, 8.3) et le moment du lancement. C'est là que la marque doit vivre (`branding-002`).
- Une texture « fantasy » (parchemin, or, typographie médiévale) poserait un risque de marque déposée (Blizzard) et
  casserait la doctrine « outil, pas affiche ».
- Critère de sortie : relancer `impeccable` sur le canvas (lot 6) et viser ≥ 30/40 sans ajouter de décoration.

Alternatives écartées : direction marquée « fantasy » — risque juridique et bruit visuel. Statu quo à 25/40 — laisse
le lancement, seul vrai moment de l'app, sans retour visuel.

### #37 — Icône tortue ou engrenages

**Recommandation : refaire l'icône avec Icon Composer à partir des engrenages laiton sur cobalt, et retirer toute trace de tortue.**
- L'app s'appelle WoWSilicon et couvre maintenant BfA et des jeux D3D9 : la tortue (héritage TurtleSilicon / Turtle WoW) n'a plus de sens.
- Les engrenages sont reconnus par les utilisateurs existants : on garde la continuité.
- Le fichier actuel intègre son cadre, son halo et son ombre (contraire à `app-icons-005`, `app-icons-012`), sans
  variantes sombre ni teintée (`app-icons-015`, `app-icons-016`). Icon Composer produit les couches et les variantes ;
  la partie raster reste lisible sur macOS 14-15.
- Nettoyage associé : `turtle.icns`, `turtlesilicon_icon.png`, `ASSETCATALOG_COMPILER_APPICON_NAME = turtle`
  (`project.pbxproj:310`, `:336`), le symbole de secours `tortoise.fill` (`MainDashboardView.swift:531`,
  `AppSupport/AppAssets.swift:40-44`) et le remplacement de l'icône du Dock à l'exécution (`WoWSiliconSwiftApp.swift:39-41`).

Alternatives écartées : garder l'image actuelle — pas de variantes sombre ni teintée, effets intégrés à l'image.
Dessiner une tortue — rattache l'app à un serveur tiers alors qu'elle n'y est plus liée.

### #38 — Options globales ou par profil ?

**Recommandation : trois portées, trois endroits. On garde « par profil » ce que le code a déjà rendu par profil.**

| Portée | Contenu | Où |
|---|---|---|
| Par profil | Graphismes, HDR, Metal HUD, terminal, vanilla-tweaks, cache WDB, x87, taille du curseur, audio (sorties, spatialisation, normalisation), variables d'environnement, lanceur tiers, raccourci de lancement | Vue **Profil** du détail (⌘5) |
| Par bouteille Wine | Chemin de la bouteille, migration, Retina (registre), Option → Alt (registre), winecfg, terminal Wine | Réglages › **Wine** |
| Globale (app) | Mises à jour, statistiques anonymes, dépendances, dépannage | Réglages › Général, Dépendances, Dépannage |

- Le code stocke déjà ces réglages dans `VersionSettings`, par profil (`MainDashboardViewModel.swift:1031-1070`,
  `:1302-1340`) : le design s'aligne sur la réalité au lieu de la contredire.
- Retina et Option → Alt agissent sur le registre de la bouteille, donc sur **tous** les profils : les montrer dans un
  écran par profil est trompeur (constat O1). Le code les recopie aussi dans le profil
  (`MainDashboardViewModel.swift` `applyOptionAsAltState`) : à simplifier lors du lot 2 (signalé à woz).
- Une question de suivi, non bloquante : faut-il « Copier les réglages depuis un autre profil… » ? À ajouter seulement si les retours le demandent (`settings-002`).

Alternatives écartées : tout global — casserait des profils qui ont besoin de moteurs différents (32 bits D9VK contre
BfA wined3d). Tout dans Réglages, avec un sélecteur de profil en haut — c'est le défaut actuel (O1), sous une autre forme.
